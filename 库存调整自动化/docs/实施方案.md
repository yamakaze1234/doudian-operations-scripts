# 库存调整自动化

用户已选择在本项目独立目录实现上一轮提出的油猴脚本方案。

目标：粘贴 SPU 和简称，按商品搜索，精确匹配真实 SKU，将目标 SKU 的现货及已有预售档库存置零，保存后回读。

技术：原生 JavaScript 油猴脚本，独立的匹配核心、页面适配器与面板；Node 内置测试器和 jsdom 验证。构建为单个可安装 user.js。

执行顺序：
- [x] 编写并运行核心测试：19 位 SPU 保真、科学计数法拒绝、格式规范化、型号差异、重复匹配、重复输入。
- [x] 实现核心与页面读取，按完整库存合计核实 SKU 扫描；不完整表格拒绝进入写入。
- [x] 编写页面测试：现货/多档预售读取、异常输入、占用库存、非目标 SKU 不变、写入后字段校验。
- [x] 实现逐商品预检、结果审阅、执行、保存回读及 JSON 导出。任何失败停止队列，不重试保存。
- [x] 构建安装文件，运行全部相关测试及语法检查，做本地页面操作验证。

页面依据（2026-09-10 只读实查）：商品行 data-row-key 为 SPU；修改库存入口 data-kora="修改库存" 的父 a；库存抽屉 .auxo-drawer-open；SKU 表格为 .optimus_fems-table，列为 SKU信息、现货库存增减、改后现货库存、预售库存、占用库存、未占用库存；真实 SKU ID 在第一列文本中；保存按钮文本为“保 存”。已检查商品有 20 条 SKU，均在 DOM 中。

执行边界：只处理普通库存，完整分列结构及可验证的库存合计。对未知布局、筛选/分页、虚拟列表不完整、占用库存非零、简称歧义、商品或店铺切换停止。简称仅统一空白、全半角、大小写和竖线，不替换型号或容量。清零库存不等于调用商品下架。

用户操作：预检只读；面板“执行清零并保存”按钮是用户对预览结果的实际提交入口。开发验证不修改真实库存。失败后重新预检可跳过已经清零的目标。

验证界限：本地测试通过不等于真实保存成功；生产提交验收需使用者执行后回读。未实测的库存模式明确拒绝。
