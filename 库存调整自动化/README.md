# 库存调整自动化

在抖店商品管理页，从 Excel 粘贴 **SPU + 简称**，匹配真实 SKU，只将命中的 SKU 现货和已有预售档库存设为 0。这里“下架”指库存清零，不调用整件商品下架。

## 安装与使用

1. 在已安装 Tampermonkey 的浏览器中，打开扩展管理面板 → 添加新脚本。
2. 用文本编辑器打开本目录的 `抖店库存调整自动化.user.js`，复制全部内容替换默认模板，保存。
3. 刷新抖店商品管理页面，左下角出现“库存调整自动化”。如扩展提示需要开启用户脚本执行权限，请按扩展提示操作。
4. 在 Excel 中将 SPU 列设置为文本，复制 SPU 和简称两列；可含标题行。已经被 Excel 舍入的 ID，改变格式不能恢复，需重新取得原始 ID。
5. 在目标店铺打开面板，粘贴两列，点击“预检匹配”。脚本会切换到“售卖中”分类并重置商品列表筛选，按 SPU 搜索，从对应商品“总库存”列旁的编辑图标打开库存窗口，只读取库存后关闭。
6. 核对面板上的店铺、SPU、真实 SKU ID、名称及现货/预售数量。匹配不到或有歧义的项目跳过，不按配置序号猜测。
7. 勾选核对框，点击“执行清零并保存”。脚本从“售卖中 → 总库存编辑图标”逐商品重新核对库存，填 0、保存、重新打开验证。若整商品库存清零，保存后的只读回查切到“已售罄”；其余仍在“售卖中”回查。全部目标原本已为 0 的商品不再次保存。
8. 点击“导出结果”保存 JSON 记录。只有“已验证清零”代表保存后回读通过。

## 匹配规则

- SPU 全程使用字符串，支持长 ID，不转成 JavaScript 数字；拒绝科学计数法。
- 简称必须对应完整 SKU 名称。统一全半角、空白、大小写和 `丨/|`，保留配置编号、型号、容量和版本。
- 不把 `5090` 当作 `5090 D`，不把 `48G` 当作 `48GB`，不采用模糊包含匹配。
- 相同 SPU 和规范化简称自动去重；跨 SPU 的同名 SKU 分开处理。

## 支持范围与异常恢复

第一版针对 2026-09-10 实查的普通库存窗口，支持“改后现货库存”或“现货库存”列，以及纯现货的“当前库存、库存增减、改后库存”布局；预售库存列可不存在，或存在但未设置预售档位。纯现货商品只清零目标 SKU 的现货字段，不创建或开启预售；有预售档位时同时清零。仍需可识别 SKU 信息和占用库存列。库存明细合计必须等于商品总库存；布局不符、未知分页/虚拟表格、占用库存非零或不可编辑字段时停止。

预检前请先完成或取消当前已有的库存编辑；执行期间使用独立标签页，不手动修改该页。切换店铺、库存变化、写入校验或保存回读失败都会停止后续商品。已提交的保存不会因“停止”而撤销。

发生“保存结果待核实”时，先在后台检查该商品，勿直接重复点保存；核实并关闭窗口后重新预检，已经清零的目标会跳过保存。失败时可能保留未保存输入，由你决定保存或取消。记录只保存在当前页面内存，刷新前先导出。

工具通过页面控件操作，不使用外部服务器，也不打包账号、Cookie 或开发机登录状态。没有自动点击整件商品“全部清零”或“下架”的行为。

## 文件和验证

- `抖店库存调整自动化.user.js`：可安装脚本。
- `src/`：匹配、库存适配、执行流程、浏览器适配、操作面板。
- `tests/`：名称/ID、DOM 库存与执行流程测试。
- `docs/实施方案.md`：范围和页面依据。

开发环境 Node.js，执行 `npm ci`、`npm test`、`npm run build`，再执行 `node --check 抖店库存调整自动化.user.js`。

本地测试与真实后台页面结构检查分开记录；本次开发未提交任何真实库存变更。真实保存后的端到端验收仍需用户使用目标清单执行，不能把本地测试当作生产验收。

## 0.1.3 更新

根据真实商品 3797170100491124774 的库存窗口，新增“当前库存 / 库存增减 / 改后库存”纯现货布局：读取并填写“改后库存”，保留“当前库存”展示。预检核对两者一致，避免覆盖未保存修改。页面只读检查完成，未提交真实库存变更。
# 0.2.0 添加现货库存

保留原有清零功能。在面板选择“添加现货库存”，填写统一增加数量（正整数），粘贴原有两列 `SPU、简称` 后预检。例如原现货 5、增加 4，预览为 9；已有预售档位及未命中的 SKU 保持原值。更改模式或数量后必须重新预检。

仍从商品管理“售卖中”查找商品。执行前重新核对原库存，保存后回读验证；保存结果未知时不自动重试。添加是累加操作，成功后若再次预检并执行，会再次增加。当前保留普通库存、无占用库存及已支持布局的限制。
