# 价格调整自动化

沿用用户已指定的库存自动化交互与视觉，独立工具放在本目录。

目标：售卖中按 SPU 搜索，通过价格旁编辑图标打开弹窗；读取完整虚拟 SKU 表格，预览旧价、新价、差额；用户核对后执行保存，再重新打开完整回读。开发期间不提交真实价格。

输入：带表头的 SPU、SKU、简称、售价，允许额外列但不参与修改；无表头接受四列 SPU/SKU/简称/售价，或三列 SPU/简称/售价。SKU ID 为空时仅以规范化完整简称唯一匹配。提供 SKU ID 时必须 ID 与名称同时一致；同一 SKU 冲突价格拒绝。

数据：ID 一律字符串；金额以整数分比较，最多两位小数，目标大于 0。配置名仅统一空白、全半角、大小写、竖线。到手价可能由活动计算，不作写入目标或固定校验项。

页面依据：2026-09-10 实查 .ecom-g-modal-content 编辑价格；表头 配置/价格/到手价/SKUID/商家编码/预览图/SKU状态；.ecom-g-table-tbody-virtual-holder 持有滚动；虚拟行 tr.ecom-g-table-row[data-row-key]，行 key 不等于真实 SKU ID；价格 input[type=number] 位于价格列；编码输入框在商家编码列。

实施与验收：
- [x] 核心输入解析、金额精度、ID/名称交叉匹配测试先失败再实现。
- [x] 页面行读取与虚拟滚动覆盖完整性；测试晚加载 SKU、行复用及滚动失效。
- [x] 串行预检、审阅、保存、回读；保存结果未知停止，不自动重试。
- [x] 面板与单文件 user.js 构建；与库存面板错开入口位置，独立命名空间。
- [x] 本地相关测试、语法及独立审查；真实页面只读核验，不宣称生产保存验收。

预检只能从工具打开的新窗口开始，以商品行 SPU、当前店铺和弹窗对象绑定上下文；期间切店、关闭/更换弹窗即停止。匹配异常项跳过，已匹配项目只在用户点击执行后修改。未匹配和名称不一致均显示原因。
